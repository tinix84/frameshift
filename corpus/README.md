# Exemplar corpus

These worked cases are the fastest way to understand FrameShift's intended
behaviour. Each directory is self-contained: read its narrative, then inspect
the intake, citation, reference result, and harness expectations.

## Available exemplars

- [`kafka-in-disguise`](kafka-in-disguise/) — a negative starting case: a
  technology request with no owned outcome. The engine asks for the missing
  outcome before optimising.

- [`tunnel-lights`](tunnel-lights/) - negative reframe case: the correct frame
  stays at the named subsystem level because upward reframing changes the owner
  and decision.
- [`bracket-weight-mandate`](bracket-weight-mandate/) - negative boundary case:
  the supplier stays within the named component boundary and records the
  customer-owned higher frame as out of scope.
